# API

All of this is importable from `ol-cad` (ESM) or available on the global `olcad` (UMD).

## `createEditor(config): Editor`

Validates the config (throws `ConfigError`, see [configuration.md](configuration.md)), registers proj4 projections, creates or attaches to the map, builds basemaps and layers and returns the editor. Layers load when the map first renders them.

### `editor.basemaps`

| Member                   | Description                                                                                                                                       |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| `list()`                 | `{ id, title, active }[]` in config order; `active` is the basemap's visibility (several may be visible after `setAllVisible(true)`).             |
| `getActive()`            | Id of the topmost visible basemap (the last in config order) or `null` when none is visible.                                                      |
| `setActive(id)`          | Shows that basemap, hides the others, emits `basemapchange` with `type: 'activate'`. Throws for an unknown id.                                    |
| `setAllVisible(visible)` | Shows every basemap (stacked, the last one on top) or hides them all. Emits `basemapchange` with `type: 'visible'` for each basemap that changed. |

### `editor.overlays`

Raster overlays (`overlays[]`): server-rendered or tiled layers between the basemap and the vector layers, each switched on its own, read-only.

| Member                                                     | Description                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| ---------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `list()`                                                   | `OverlayInfo[]` in drawing order, bottom first: `{ id, title, type, visible, opacity, minZoom?, maxZoom?, legendUrl?, attribution?, queryable, group? }`.                                                                                                                                                                                                                                                                                                       |
| `get(id)` / `has(id)` / `getConfig(id)`                    | Info of one overlay (throws for an unknown id) / whether the id names an overlay / its resolved configuration.                                                                                                                                                                                                                                                                                                                                                  |
| `add(config)`                                              | Adds an overlay at runtime, validated like `overlays[]`; drawn below the vector layers and above the other overlays. Emits `overlaychange` with `type: 'add'`. Throws when a layer or overlay has the id.                                                                                                                                                                                                                                                       |
| `remove(id)`                                               | Emits `overlaychange` with `type: 'remove'`.                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `setVisible(id, visible)`                                  | Emits `overlaychange` with `type: 'visible'` when it changed.                                                                                                                                                                                                                                                                                                                                                                                                   |
| `setAllVisible(visible)`                                   | Shows or hides every overlay; emits `overlaychange` with `type: 'visible'` for each one that changed. Layers are untouched.                                                                                                                                                                                                                                                                                                                                     |
| `setOpacity(id, opacity)` / `setZoomRange(id, min?, max?)` | Conveniences over `layers.setStyle` with the overlay's style `{ opacity, minZoom?, maxZoom? }`; `undefined` lifts a zoom limit. Emit `overlaychange` with `type: 'style'`.                                                                                                                                                                                                                                                                                      |
| `getLegendUrl(id, resolution?)`                            | The configured `legendUrl`, else for WMS overlays the service's GetLegendGraphic URL (with `SCALE` for `resolution`), else `undefined`.                                                                                                                                                                                                                                                                                                                         |
| `getExtent(id)` / `fit(id, options?)`                      | The configured data extent in the view projection, or `null` / fit the view to it; `false` when none is configured.                                                                                                                                                                                                                                                                                                                                             |
| `featureInfo(coordinate)`                                  | GetFeatureInfo at a map position (view projection) for every WMS overlay that is `queryable`, visible and drawn at the current zoom: `Promise<FeatureInfoResult[]>` with `{ overlay, title, features, error? }` per overlay (`features` are `ol/Feature`s carrying the server's properties, a failed request its `error`). The inspect click does the same and emits `featureinfo`; `readFeatureInfo(text, infoFormat)` and `featureInfoUrl(...)` are exported. |

Overlays share the drawing order and the style store with the vector layers: `layers.getOrder()`, `setOrder`, `moveLayer`, `resetOrder`, `isOrderCustomized`, `getStyle`, `setStyle` (a style with a stroke, fill, point, label or text section throws `StyleError`), `resetStyle`, `isStyleCustomized`, `hasExpressionStyle` (always `false`), `exportStyles`, `importStyles` and `resetStyles` take overlay ids; `list`, `get`, `setVisible` and the other members stay vector-only and throw for an overlay id. New overlays and an order stored before overlays existed keep them below the vector layers. Overlay layers carry the property `olcad:overlay` (`OVERLAY_ID_PROPERTY`) and never `olcad:layer`, so hit detection, snapping and the tools ignore them; `createRasterLayer(spec, ctx)` is the factory basemaps and overlays share.

### `editor.discovery`

Layers and overlays added from service capabilities ([`discover[]`](configuration.md#discover)). Discovery starts when `createEditor` returns and runs in the background; the entries arrive through `layers.add` / `overlays.add`, so `layerchange` / `overlaychange` (`add`) fire for each.

| Member        | Description                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| ------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ready`       | `Promise<DiscoveryStatus[]>` that settles when every configured source is done or failed; it never rejects. A `view.fit` with `layers` is applied again afterwards so discovered extents count.                                                                                                                                                                                                                                                                            |
| `status()`    | `DiscoveryStatus[]`, one per source (configured ones first, then those of `run`): `{ state: 'pending' \| 'done' \| 'failed', source: { type, url }, added, skipped, error? }`.                                                                                                                                                                                                                                                                                             |
| `run(source)` | Discovers one more source, validated like `discover[]` (throws `ConfigError`). Resolves `DiscoveryResult` `{ source, added, skipped }`; rejects after `discoveryerror` when the capabilities cannot be read. `skipped` entries are `{ name, reason, error? }` with `reason` `'exists'` (the id is a layer or overlay already), `'no-geometry'`, `'describe-failed'` (the DescribeFeatureType request or schema failed) or `'unsupported'` (the built config was rejected). |

```js
const editor = createEditor({ target: 'map', discover: [{ type: 'wfs', url: '/geoserver/wfs' }] });
const [wfs] = await editor.discovery.ready;
console.log(wfs.state, wfs.added); // 'done', ['topp:roads', …]
```

### `editor.groups`

Groups of layers and overlays (`groups[]`, `layers[].group`, `overlays[].group`). A group has no visibility of its own: it shows or hides its members, which emit `layerchange` / `overlaychange` as usual; there is no group event.

| Member                    | Description                                                                                                                                                                                                                                                             |
| ------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `list()`                  | `GroupInfo[]`: the declared groups in config order, then the groups only members name (title = id), each `{ id, title, collapsed, layers, overlays }` with the member ids in drawing order, bottom first. A declared group without members is listed with empty arrays. |
| `setVisible(id, visible)` | Shows or hides every member layer and overlay. Throws for an unknown group.                                                                                                                                                                                             |

## Export

`editor.exportLayers(layerIds, { format, projection?, decimals?, dimensionsAsDrawn? })` returns an `ExportResult` `{ content, mimeType, extension, filename, featureCount, skipped }`; nothing is downloaded or sent (the UI's [`<olcad-export-dialog>`](ui.md#olcad-export-dialog) downloads it). Any layer can be exported: configured, read-only, draft and local ones. The same writer is exported as `exportLayers(layers, options, viewProjection)` for features outside an editor; `EXPORT_FORMATS` lists the formats for a UI.

With `dimensionsAsDrawn: true`, the objects of dimension layers are written as they are drawn, for CAD or print: each dimension becomes its parts, each with `part` (`'line'`: dimension, extension and leader lines and arcs; `'terminator'`: arrow heads as polygons; `'mark'`: dots, level marks, the running origin, as points; `'text'`: a point with `text`, `rotation` in degrees counter-clockwise, `height` in metres on the ground (`textSize` × `referenceScale`) and `align`), the source object's id as `dimension` and its `dimType`. Other layers are written unchanged. `drawnDimensions(features, config, projection, locale?)` is the same conversion for features outside an editor.

| `format`  | File                                                                                                                                                                                                                                                    |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `geojson` | One FeatureCollection; every feature gets the property `layer` (`_layer` when it already has a `layer` property). `projection` default `EPSG:4326`; another EPSG code adds a `crs` member (`urn:ogc:def:crs:EPSG::25832`).                              |
| `kml`     | Always EPSG:4326. One `<Folder>` per layer, named by its title; attributes as `ExtendedData`; no styles.                                                                                                                                                |
| `gml`     | GML 3.2: a `gml:FeatureCollection` with one feature type per layer (element named after the layer id, namespace `urn:ol-cad:export`), `gml:id` `{layer}.{id}`, `srsName` = `projection` (default EPSG:4326, written latitude first as the CRS defines). |
| `gpx`     | Always EPSG:4326. Points become waypoints, lines routes, multi-lines tracks (waypoints first); polygons and multi-points are skipped and counted in `skipped`. Objects without a `name` get `{layer title} {id}`.                                       |

`decimals` defaults to 7 for degrees and 3 for metric CRS. In XML formats, properties whose names are not valid element names are left out and object values are written as JSON text. The file name is the layer title for one layer, `export-YYYY-MM-DD` for several. Throws for no layers, an unknown layer or format, or an unregistered projection.

## Import

`editor.import` reads a file's text and inserts its objects; the UI's [`<olcad-import-dialog>`](ui.md#olcad-import-dialog) wraps it.

| Member                               | Description                                                                                                                                                                                                                                                                                                                                                                                                                       |
| ------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `read(text, { filename?, format? })` | `ImportPreview` `{ format, dataProjection, groups, skipped }`. The format comes from `format`, else the file extension (`.geojson`/`.json`, `.topojson`, `.kml`, `.gml`/`.xml`, `.gpx`), else the content; GML 2, 3 and 3.2 are told apart by namespace and coordinates. Throws `ImportError` with a readable message (invalid JSON or XML, a CRS that is not registered).                                                        |
| `targetsFor(group)`                  | Ids of the layers that can take every object of the group: insert allowed and the same geometry type, its multi-part form, or `Any`.                                                                                                                                                                                                                                                                                              |
| `apply(preview, targets?)`           | Inserts the groups as **one command** (one undo step). `targets[group.key]`: `{ type: 'new', title? }` (default: a new [local layer](#editorlocallayers) with the group's fields), `{ type: 'layer', id }` or `{ type: 'skip' }`. Returns `ImportResult` `{ created, inserted, skipped, droppedAttributes }` and emits `import`. Throws (creating nothing) when a target cannot take its group or validation rejects the command. |

- **Groups** (`ImportGroup` `{ key, name, geometryType, features, fields, invalid }`): first by the file's own grouping — the `layer` property our GeoJSON export writes, TopoJSON objects, top-level KML folders (placemarks outside folders form one more group), GML feature types — then split into points, lines and polygons; a group with single and multi parts gets the multi type. Names: the folder / layer / feature type, else the file name, with ` – points|lines|polygons` when split.
- **Geometry**: read into the view projection from the file's CRS (GeoJSON `crs`, GML `srsName`; KML, GPX and TopoJSON are EPSG:4326); heights and measures are dropped; geometry collections and objects without geometry are skipped; invalid geometries (`validateGeometry`) are left out and counted in `invalid`.
- **Attributes**: names become identifiers (`street name` → `street_name`, with the original as `label`); types are inferred (`integer`, `number`, `boolean`, else `string`), from the text of KML and GML values too. Into an existing layer, only the schema's fields are kept (over its defaults, numbers and booleans converted from text); the others are reported in `droppedAttributes`.
- Inserts carry `imported`, so the attribute popup stays closed. Objects in new local layers stay out of the change set; objects inserted into a server layer are tracked like drawn ones. Undo removes the objects; local layers created by the import remain, empty.
- Also exported: `readImport(text, { filename?, format?, viewProjection })`, `applyImport`, `importTargets`, `IMPORT_FORMATS`, `ImportError` and the types `ImportApi`, `ImportFormat`, `ImportFormatInfo`, `ImportGroup`, `ImportPreview`, `ReadImportOptions`, `ImportTarget`, `ImportResult`, `ImportContext`.

## Custom tools

`BaseTool`, `pickDimensionLayer(layers)` (the layer a dimension tool draws into) and the `Tool` / `ToolContext` types are exported for hosts that want to add tools: implement `id`, `canActivate(ctx)`, `activate(ctx)` (set `this.interactions` before calling `super.activate`), and submit every change through `ctx.execute`. A multi-step tool implements `getPrompt()` and calls `ctx.promptChanged()` whenever the next step begins; a step that asks for a dimensionless number (a count, a factor) implements `handleValue(value)` and returns `true` to take a number typed without a unit; a step that asks for a length (a distance, a height) implements `handleLength(metres)`, which receives the typed length converted to metres; both are offered before a length is resolved as a distance; a step that asks for text (a name) implements `handleText(text)`, offered before any parsing; a step that expects the user to type (text or a value) returns `'text'` / `'value'` from `getInputRequest()`, so the input bar focuses and highlights itself; `isIdle()` returns `true` while the tool has nothing in progress, so a click on a dimension's value opens the value editor instead of reaching the tool (the dimension tools at their first step; a station line waiting for its next point); `ctx.done()` ends the tool itself (as `editor.tools.deactivate()`), `ctx.templates` reaches the template store, `ctx.measurements` the measurement store (`add`, `setLive`); a tool that changes no data sets `readOnly = true` and then runs with edit mode off too; `ctx.getStraightedgeAngle()` gives the straightedge angle for shapes aligned with it, `ctx.getProjection()` the view projection (for `unitsPerMetre` and `distanceMetres`) `ctx.getCurveTolerance()` the chord tolerance in metres for linearized curves, `ctx.getLengthUnit()` and `ctx.formatLength(metres)` the default unit for prompts (a prompt may also contain `{unit}`, which `editor.tools.getPrompt()` replaces with its symbol); `PointPickInteraction` (exported) hands a tool snapped clicks and moves plus the raw pointer position, and `pickTolerance(ctx)` is the grip pick radius in map units; the editor emits `toolprompt` and `<olcad-input-bar>` shows the text. Registration of host tools on the editor is planned for milestone 6.

## Edit mode

A single boolean on the editor, toggled by `setEditMode` and by the toggle in `<olcad-toolbar>`. It is the switch between viewing and editing; what it enables beyond the flag is defined with the tools in milestone 4 (tools only activate in edit mode, except read-only tools such as the measure tools, which also run while viewing).

While edit mode is on, the core draws a CAD-style crosshair in the map viewport: two one-pixel lines spanning the whole map on both axes that follow the pointer, with a small square (the pick box) at their crossing, and hides the native cursor over the map. The lines are rotated by the straightedge angle (see `editor.straightedge`). The overlay (`div.olcad-crosshair`, inline-styled, `pointer-events: none`) hides over OpenLayers controls and when the pointer leaves the map. Size and colour come from the `cursor` config (`pickBoxSize`, `color`); `cursor.crosshair: false` disables it. The map target element carries the class `olcad-edit-mode` (exported as `EDIT_MODE_CLASS`) meanwhile. Everything is restored by `setEditMode(false)` and by `destroy()`, so a host-owned map keeps its own cursor. Hosts can use `editmodechange` or the class to show or hide their own editing UI.

## Projections and measurement

Feature coordinates in memory are always in the view projection. The data projection of each loaded feature is kept alongside its original geometry (`getOriginalGeometry`) so the change set can be exported in the layer's data projection without round-trip loss. Measurement and numeric input (milestone 5) go through a projection-aware module; in `EPSG:3857` lengths are corrected for the scale at the working location.
