# Changelog

All notable changes to this project are documented here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project uses
[Semantic Versioning](https://semver.org/).

## [Unreleased]

### Added

- Release workflow: a `v*` tag builds the package in GitHub Actions and attaches `ol-cad-<version>.tgz`, `ol-cad.umd.js`, `ol-cad.umd.js.map`, `ui.css`, a `SHA256SUMS` file and build provenance attestations (`gh attestation verify`) to the GitHub release, with the version's CHANGELOG section as notes; a tag whose version is missing from `package.json` or `CHANGELOG.md` is refused. A CI workflow runs lint, typecheck, unit tests, build and the Playwright suite on every push and pull request. `scripts/release-assets.sh` and `scripts/changelog-section.js` work locally too; `docs/releasing.md` describes the steps.
- Dimension value editor: `<olcad-dimension-input>` opens an inline box at a dimension's value when it is clicked on the map in edit mode (no tool, the select tool, or a tool with nothing in progress — `Tool.isIdle`, the dimension tools at their first step and a station line waiting for its next point); the box is pre-filled with the field value in the layer's unit (`station offset` for a station, `t <text>` for a free text) or shows the GIS value as placeholder; Enter saves, an empty box or `-` clears, Escape cancels. Core: the click is hit-tested against the drawn texts before any interaction sees it, selects the dimension and emits `dimensionvalueclick`; `editor.dimensions.input(feature, text)` (the command-line grammar for one dimension: numbers, `station offset`, `-`, `t <text>`), `labels(feature)` and `labelAt(pixel)`; `InputResult` variants `{ fieldValue, unit }` and `{ freeText }`. Shared label geometry `dimensionLabels`, `dimensionLabelAnchors`, `labelColor`, `TEXT_GAP_MM` (types `DimensionLabel`, `DimensionLabelAnchor`) used by the renderer, the grips and the hit test.
- New config option `layers[].dimension.computedColor` (default `'#6b7280'`): the text colour of values computed from the map, so GIS values and field values are told apart by colour; `color` colours field values, lines and marks, `deviationColor` deviating field values. A station's two values are coloured each by its own state.

### Changed

- The dimension tools no longer need an active dimension layer: activating one makes a dimension layer active by itself — the active layer when it is a dimension layer, else the first dimension layer in the layer list that allows inserts (`pickDimensionLayer`, exported) — and the previously active layer comes back when the dimension tools end (unless another layer was chosen meanwhile). The toolbar buttons are greyed out only when no such layer exists; making a non-dimension layer active while a dimension tool runs ends the tool.
- **Breaking (behaviour):** the dimension tools insert the dimension as soon as it is drawn — the linear tools when the dimension line is placed (a tie with its second point), angular with the arc, radial with the placement, stations with every recorded point (Enter writes the end measure at once), a slope from two levels with the second level — with the GIS value only; the final "value" step, `Enter keeps`, the typed field value and `t <text>` in the tools are gone. Spot levels still type their height and free slopes their percentage. The field value is entered afterwards by clicking the value, in the command line or through the API.
- **Breaking:** `layers[].dimension.showComputed` defaults to `'plain'` (brackets stay available); `-` for a selected dimension clears the free text as well as the field value; `dimensionGrips` takes the layer's dimension config as fourth argument (the text grip sits at the drawn value, and `running` dimensions have none).
- Dimension grips, associative dimensions and drawn export (dimensions milestone D7): the Vertices tool (`modify`) edits a selected dimension through grips: the definition points (references re-recorded, GIS value refreshed), the dimension line or arc (`offset`) and the value of linear dimensions (`textPosition`). New config option `layers[].dimension.associative` (default `false`): the dimensions of such a layer follow a referenced object that is reshaped, in the same undo step as the change, instead of turning stale. `ExportOptions.dimensionsAsDrawn` writes dimension objects as their drawn parts (`part`: `line`, `terminator`, `mark`, `text` with `rotation`, `height` and `align`) in every export format; `<olcad-export-dialog>` offers it as a checkbox when a dimension layer exists. Exported `dimensionGrips`, `moveGrip`, `drawnDimensions`, type `DimensionGrip`.
- Linear dimension tool (dimensions milestone D2): `dimension-linear` draws into the active dimension layer: two snapped (or typed) points, the dimension line placed with the pointer or by a typed offset, then the field value — Enter keeps the GIS value, a typed length is the field value, `t <text>` a free text. Variants `{ method: 'aligned' }` (true distance) and `'rotated'` (the distance along the straightedge angle, stored as `rotation`); the renderer, `dimensionValues` and validation support `rotated`. The dimension in progress is drawn in the layer's own style; the insert carries `dimType`, `offset`, `gisValue`, `fieldValue`, `text` and the schema defaults and is selected. Toolbar: a **Dimension** toolbar with the flyout button Linear dimension (icons `dimensionAligned`, `dimensionRotated`) on the test page and in the vanilla example. `ToolContext.getLocale()`.
- Field values of existing dimensions: `editor.dimensions` (`isDimension`, `values`, `setFieldValue(feature, metres | null)`, `inputTarget`); with one dimension selected and no tool running, a length typed in the command line sets its field value and `-` clears it (`InputResult` `{ ok, text, fieldValue }`; `<olcad-input-bar>` prompts for it). `<olcad-attribute-form>` offers Field value and Text on every dimension layer (`DIMENSION_FORM_FIELDS`, `layerFormFields`) and opens no popup after a dimension insert.
- Survey and landscape dimensions (dimensions milestone D6): tool `dimension-survey` with `{ method: 'station' }` (orthogonal survey: a measuring line, then each point by station and offset, both field values typed in one entry `12.47 3.05`; Enter writes the end measure; the points of a line share `chain`), `'level'` (spot level: point, label position, height in metres, any sign; marks: open triangle for finished / existing, filled for structural / planned levels, a cross for surveying; `levelKind`) and `'slope'` (from two spot levels, downhill, referenced, or a free arrow with a typed percentage). New `dimType`s `station`, `level`, `slope`; `fieldOffset`, `gisOffset`, `levelKind`; `DimensionValues.gis` may be `null` and `second` carries a station's offset; `unit` `'%'`. Dimension layers validate their objects themselves (a station may end at the line's end). Command line: heights and slopes may be negative, stations take `station offset`; the table writes `station / offset`, signed heights and percentages; the form offers Field offset and Level kind. Flyout Survey dimension (icons `dimensionStation`, `dimensionLevel`, `dimensionSlope`). Exported `formatLevel`, `formatSlope`, `finiteOf`, `LEVEL_KINDS`, type `LevelKind`.
- Angular and radial dimensions (dimensions milestone D5): tools `dimension-angular` (`{ method: 'points' }`: leg, vertex, leg, snapped and referenced; `'segments'`: two picked edges meeting at the intersection of their lines, also outside them; the pointer chooses the inner, reflex or one of the four angles and the arc radius) and `dimension-radial` (`'radius'`, `'diameter'`, `'arc'`: the circle is fitted to the evenly turning vertices of the clicked curve, `fitCircleRun`, with three points on the arc as the fallback; the pointer places the leader or the arc dimension). New `dimType`s `angular` ([leg, vertex, leg], counter-clockwise, `offset` = arc radius), `radius`, `diameter` ([centre, point on the circle]) and `arc` ([centre, start, end]); drawn with arcs, leaders, centre cross and the prefixes `R`, `Ø`, `⌒`. New config options `layers[].dimension.angleUnit` (`'deg'` / `'gon'`, gon for the surveying preset) and `angleTolerance`; angles are stored in degrees and typed and shown in the layer's unit (`87,5°`, `97,2222 gon`), also in the command line for a selected angular dimension and in the table. Flyout buttons Angular dimension and Radial dimension on the Dimension toolbar (icons `dimensionAngular`, `dimensionAngularSegments`, `dimensionRadius`, `dimensionDiameter`, `dimensionArc`). Exported `formatDimensionAngle`, `sweepAngle`, `toAngleUnit`, `fromAngleUnit`, `dimensionPointCount`, `fitCircleRun`, type `DimensionAngleUnit`; `DimensionValues.unit`.
- Dimension references and the stale check (dimensions milestone D4): the dimension tool records in `refs` which object, vertex, segment midpoint or point on a segment each point was snapped to (`ToolContext.getSnap`). After every change, undo, redo, load and projection switch the editor derives which dimensions are **stale** (a referenced point moved by more than 1 mm or its object is gone): drawn dashed with ⚠, status `stale` in `dimensionValues` and the table, event `dimensionstale`; never written into the objects. `editor.dimensions.isStale`, `listStale`, `update` (back onto the objects, field value kept, one command), `updateStale`, `detach`; the attribute form shows a notice with Update and Detach, the table **Update N stale**. `changes.accept({ idMap })` rewrites references to temporary ids. Validation checks `refs`; seed dimensions 1001 and 1002 reference parcel 1. Exported `referenceFor`, `resolveReference`, `referencesOf`, `referencedPoints`, `isStale`, `isRefs`, `remapReferences` and the types `DimensionReference`, `DimensionRefs`, `SnapSource`.
- Chains, baselines, running and tie dimensions (dimensions milestone D3): `dimension-linear` variants `chain` (consecutive spans on one line in the first span's direction), `baseline` (every point from one origin, the lines stacked 8 mm apart at the reference scale), `running` (every point from one origin on one line with cumulative values, an origin circle with "0" and outward arrows; new `dimType: 'running'`) and `tie` (survey tie distance on a dashed line, no dimension line step; new `dimType: 'tie'`). The spans of a set share `rotation` and a `chain` id and are entered point after point until Enter or Escape; each is its own command with its own field value. Flyout icons `dimensionChain`, `dimensionBaseline`, `dimensionRunning`, `dimensionTie`; `DIMENSION_PAPER_MM.baselineSpacing`, `originRadius`.
- `<olcad-feature-table>` shows GIS value, field value, difference and status for dimension layers and marks deviating dimensions (`data-status="deviates"`).
- Local dimension layers: `editor.localLayers.create({ …, geometryType: 'LineString', dimension: { preset } })`, kept by export / import; `<olcad-layer-editor>` offers **Dimensions** with a drawing standard (Architecture, Surveying, Landscape).
- Dimension layers (dimensions milestone D1): new config option `layers[].dimension` (`true` or `{ preset, referenceScale, textSize, terminator, tolerance, showComputed, color, deviationColor, font }`; geometry type `LineString` or `Any`, not combinable with `text`) makes two-point line objects draw as aligned dimensions: extension lines, the dimension line at the `offset` property, terminators (tick, arrow, dot) and the value, sized in paper millimetres at a reference scale. Presets after DIN / ISO: `architecture` (DIN 1356-1: cm below 1 m, mm as superscript, `2,01⁵`; 1:100, ticks), `surveying` (m with cm; 1:500, arrows; the default) and `landscape` (m with cm; 1:250, dots). The value is the GIS value measured like the measure tools (in brackets until a field value is set) or the `fieldValue` property (plain); a field value off by more than `tolerance` is drawn in `deviationColor`; `text` replaces the value (`{value}` inserts it); the decimal separator follows `locale`. Commands on dimension layers are checked (codes `dimension-type`, `dimension-points`, `dimension-value` in `en` and `de`). Exported `dimensionStyleFunction`, `dimensionValues`, `formatDimension`, `formatDimensionNumber`, `decimalSeparator`, `fieldValueOf`, `validateDimensionFeature`, `DIMENSION_TYPES`, `SUPPORTED_DIMENSION_TYPES`, `DIMENSION_DEFAULTS`, `DIMENSION_PRESETS`, `DIMENSION_PAPER_MM` and the types. Dimension layers are never the target of the draw and construction tools, the draft move, file import or the template fallback (a dimension copied as a template goes back into its own dimension layer). The test configuration has a `dimensions` layer with seed data; the vanilla example a small dimension layer.

- The test configuration's `dimensions` layer keeps only `offset` in its schema; field value and text come with every dimension layer.

## [0.1.1] - 2026-10-15

### Added

- `ol-cad/ui` adds every `<olcad-*>` tag to TypeScript's `HTMLElementTagNameMap`, so `querySelector('olcad-toolbar')` and `createElement('olcad-dock')` return the element classes.
- `isLocalLayerPersisted(editor)` and `onLocalLayerPersistenceChange(listener)` tell whether `persistLocalLayers` keeps an editor's local layers in browser storage.
- CSS custom property `--olcad-toolbar-layer-width` (default `12em`), the width of the toolbar's "Layer: …" label.
- `docs/frameworks.md`: React and Vue sections (components, JSX typings, `shallowRef`, bundle size); the Angular example uses a column layout, a basemap title and explains what the change counter counts. `docs/change-set.md` states that local layers and the draft layer are not part of the change set; `docs/ui.md` says how to size `<olcad-dock>`.

### Fixed

- React 19 crashed with "Cannot set property name … which has only a getter", and Vue warned and dropped the attribute, for `<olcad-panel name>` / `<olcad-toolbar name>`: `name`, `reveal` (`<olcad-layer-list>`, `<olcad-attribute-form>`) and `popup` (`<olcad-attribute-form>`) are now properties with setters that reflect to the attribute.
- The basemap was drawn dimmed in the dark theme, because the browser darkens the map canvas under `color-scheme: dark`; the theme keeps `color-scheme: light` on `.ol-viewport canvas`.
- `<olcad-layer-list>`: the Edit button of the active layer cleared the layer while edit mode was off; it now switches edit mode back on, and it shows as pressed only while edit mode is on. The storage detail and tooltips of local layers said "this browser" although the layers were in memory; they now say `memory (lost on reload)` unless `persistLocalLayers` runs. The New layer tooltip says "Create a local layer".
- `<olcad-toolbar>`: the buttons after the "Layer: …" label moved when the active layer changed; the label has a fixed width, cuts long names off with an ellipsis and shows them in full as a tooltip.

## [0.1.0] - 2026-10-14

First public release, on GitHub (package file attached to the release; not on npm).

### Added

- `docs/frameworks.md`: framework integration rules and an Angular guide (styles, bundle budget, a standalone component with setup and teardown). The README documents installing from the GitHub release (package file by URL; `ol-cad.umd.js` and `ui.css` for script tags) and the development version, the toolbar's `tools` attribute, the page-wide theme and local layer persistence; `docs/api.md` explains the temporary ids of new objects.

### Fixed

- The ESM build and its type declarations import `ol` subpaths and their own modules with full file extensions (`ol/Feature.js`, `./core/Editor.js`), so the package resolves in Node, webpack 5 and TypeScript with `moduleResolution: node16 / nodenext`, not only in Vite.

### Added

- Layer styles: View → Layer styles… (`<olcad-layer-style-dialog>`) lets users reorder the layers (drag and drop, up / down) and change their look live — line colour / width / pattern, fill colour and opacity, point radius / fill / outline, a label from an attribute (size, colour, halo), text colours of text layers, layer opacity and zoom range — with Reset layer / Reset all; `persistLayerStyles` keeps it in the browser. Core: `editor.layers.getStyle`, `setStyle`, `resetStyle`, `isStyleCustomized`, `hasExpressionStyle`, `setOrder`, `moveLayer`, `resetOrder`, `isOrderCustomized`, `exportStyles`, `importStyles`, `resetStyles`; `layerchange` types `style` and `order`; `list()` follows the drawing order and vector layers get `zIndex` from it (`LAYER_Z_INDEX_BASE`). Exported `LayerStyle`, `StrokeDash`, `LayerStylesJson`, `LayerChangeType`, `styleFromFlat`, `flatFromStyle`, `validateStyle`, `styleSections`, `parseColor`, `rgba`, `StyleError`, `OlcadLayerStyleDialog`, `persistLayerStyles`; icons `arrowUp`, `arrowDown`, `palette`.
- Length units: typed lengths may carry a unit (`5ft`, `5 ft`, `3'`, `12.5 m`, `@3ft,4ft`, `@10 mi<45`; `m`, `km`, `cm`, `mm`, `ft`, `us-ft`, `in`, `yd`, `mi`, `nmi` and their usual spellings); a length without one is in the default unit. New config option `units.length` (`'auto'` default: the view projection's unit — `m`, `ft` or `us-ft`, metres for geographic CRS — following projection switches; or a fixed unit) and `editor.units` (`getLength`, `getLengthSetting`, `setLength`, `toMetres`, `fromMetres`, `formatLength`, `formatArea`), event `unitschange`. Lengths and areas are displayed in the default unit's system (metric m / km, m² / ha / km²; feet ft / mi, ft² / ac / mi²): measurement labels (rewritten on a unit change), `<olcad-measure-results>`, the `<olcad-feature-table>` geometry and text-height columns, the command line echo and tool prompts. New element `<olcad-unit-select>` (CRS panel of the test page, a Units panel in the vanilla example). Tool contract: `Tool.handleLength(metres)` for steps that ask for a length, `ToolContext.getLengthUnit` / `formatLength`, `{unit}` in prompts; `InputResult` `{ ok, text, length }`. Exported units module (`LENGTH_UNITS`, `crsLengthUnit`, `toMetres`, `fromMetres`, `unitFromText`, `isLengthUnit`, `lengthUnitInfo`, types `LengthUnit`, `LengthUnitInfo`, `UnitsApi`, `UnitsConfig`); `formatLength` / `formatArea` and `computeMeasurement` take an optional unit; `parseInput(text, defaultUnit?)`; `MeasurementStore.relabel()`.
- Toolbars and panels can be shown and hidden: `<olcad-dock>` `listPanels()`, `setPanelVisible(name, visible)`, `setAllPanelsVisible(visible)`; visibility is part of the layout (`PanelPlacement.hidden`, stored under `storage-key`, restored by `resetLayout()` to the authored state). Panel attribute `no-toggle` leaves visibility to the panel's content (`<olcad-feature-table>` sets it on its panel). `bindPanelMenu(menu, dock)` fills a menu with Show all / Hide all toolbars and panels and a checkbox per toolbar and panel; `OlcadMenu.refresh()` decorates items added later. The test page's View menu and a new View menu in the vanilla example use it.
- Import: `editor.import` (`read`, `targetsFor`, `apply`) reads GeoJSON, TopoJSON, KML, GML 2 / 3 / 3.2 and GPX files in the browser into groups of one geometry type (by the file's layer property, KML folder or GML feature type, then points / lines / polygons), with inferred attributes, the file's CRS and invalid geometries left out, and inserts them into new local layers or existing layers that take them as one undo step; event `import`, `ImportError`. Inserts carry `imported` (`insertFeature(…, { imported })`, `featureinsert.imported`), so the attribute popup stays closed. UI: `<olcad-import-dialog>` (file input and drop zone, per-group name and target, event `olcad-import`); File → Import… on the test page, an Import button in the vanilla example. Exported `readImport`, `applyImport`, `importTargets`, `IMPORT_FORMATS`, `ImportError`, `OlcadImportDialog`, `IMPORT_EVENT` and the types.
- Export: `editor.exportLayers(layerIds, { format, projection?, decimals? })` writes the current objects of any layers into one file's text — GeoJSON (one FeatureCollection with a `layer` property, any CRS), KML (one Folder per layer, EPSG:4326), GML 3.2 (one feature type per layer, any CRS) or GPX (waypoints, routes, tracks; polygons skipped) — and returns `{ content, mimeType, extension, filename, featureCount, skipped }`. Exported `exportLayers`, `EXPORT_FORMATS` and the types. UI: `<olcad-export-dialog>` (layer checklist, format, CRS, download, event `olcad-export`) and `downloadFile`. The test page has File → Export…, the vanilla example an Export button.
- Local layers: `editor.localLayers` (`list`, `get`, `has`, `create`, `rename`, `setFields`, `remove`, `export`, `import`) lets users create layers in the client with a geometry type and attributes; they are fully editable and snappable, and their edits never enter the change set. `setFields` moves values of renamed attributes and drops removed ones. JSON export / import (GeoJSON in EPSG:4326, `LocalLayerImportError` naming the path); event `locallayerchange`; `layerchange` gained the types `title` and `schema`; `LayerInfo.local`. UI: `<olcad-layer-editor>` dialog (name, geometry type, attribute rows, two-step delete), a New layer button in `<olcad-layer-list>` and a Settings button on local rows (icons `addLayer`, `settings`), and `persistLocalLayers(editor, storage?, options?)` with `indexedDbStorage()` to keep them in IndexedDB. The test page and the vanilla example persist local layers. Exported `LOCAL_GEOMETRY_TYPES`, `LocalLayerImportError`, `LocalLayersApi`, `LocalLayerDefinition`, `LocalLayerInfo`, `LocalLayersJson`, `LocalLayerChange`, `LocalGeometryType`, `OlcadLayerEditor`, `persistLocalLayers`, `indexedDbStorage` and the storage types.
- Table view: new element `<olcad-feature-table>` shows the objects of one layer as rows (id, schema fields, text and height for text layers, geometry type with projection-aware length or area), with sorting by column, a text filter, change markers (`data-state` inserted / updated), selection sync in both directions (click, Ctrl / Cmd toggle, Shift range) and zoom on double click; `show(layerId)`, `close()`, attribute `layer`; it hides its enclosing panel while closed. `<olcad-layer-list>` has a Table button per layer row (`.olcad-layer-list__table`, icon `table`) that opens or closes it. Exported `OlcadFeatureTable`, `featureTablesOf`, `onFeatureTableChange`; new icons `table` and `close`; CSS custom property `--olcad-table-height`. The test page and the vanilla example dock the table at the bottom, above the command line and the CRS bar.
- Steps that expect typing focus the command line: `Tool.getInputRequest()` (`'text'` / `'value'` / `null`), `editor.tools.getInputRequest()` and `toolprompt.input`; the text tool (height, text), template copy (name), mirror (copy question), regular polygon (sides), offset (distance), scale (factor), circle (radius) and ellipse (half-axis) report it. `<olcad-input-bar>` then focuses its input, selects its content and highlights itself (`olcad-input-bar--awaiting`, `data-input`, placeholder), never taking the focus from an open dialog or another field, and gives the focus back when the step ends. The input bar also shows the prompt of a read-only (measure) tool while edit mode is off.
- Text tool (`text`): click (or type) the insert point, type the text height in metres (Enter keeps the offered one: the layer's `text.height`, then the last one), type the text in the command line; the text is inserted as a point object with `text`, `textHeight` and `textRotation` (the straightedge angle) into the active text layer or the draft layer, selected, with the attribute popup for schema layers. New config option `layers[].text` (`true` or `{ property, heightProperty, rotationProperty, height, color, haloColor, font }`; point layers only) makes a layer a text layer: its texts are drawn sized in metres on the ground, rotated and with a halo, and are clickable (`textStyleFunction`, `textStyle`, `featureText`, `TEXT_DEFAULTS`). The draft layer is a text layer. Toolbar button Draw text (icon `drawText`) in the Draw toolbar; the test configuration has a new `labels` text layer with seed data. Exported `TextTool`, `TEXT_PROMPTS`, `TextStep`, `textTarget`, `TextTarget`, `TextConfig`, `ResolvedTextConfig`.
- Measurement toolbox: read-only tools `measure-distance` (polyline, segment lengths and total; Enter finishes), `measure-area` (corners; area and perimeter) and `measure-angle` (first point, vertex, second point), with Alt+click on a line or polygon to measure it directly; snapped and typed points; Backspace and Escape step back. They run with edit mode off too (new `Tool.readOnly`: `tools.activate` / `canActivate` allow read-only tools without edit mode, `setEditMode(false)` keeps them, inspect clicks pause and snapping and numeric input work for them). `editor.measurements` (`list`, `get`, `add`, `remove`, `clear`, `getLive`) keeps finished measurements on a labelled overlay until removed; events `measurechange` and `measure` (live). Values in metres, m² and degrees: planar in true-to-scale metric projections, exact on the projection sphere in Web Mercator, `ol/sphere` in geographic ones (`measureLength`, `measureArea`, `measureAngle`, `formatLength`, `formatArea`, `formatAngle`, `computeMeasurement`, `MEASUREMENT_MIN_POINTS`). Toolbar buttons Measure distance / area / angle and Clear measurements (icons `measureDistance`, `measureArea`, `measureAngle`, `measureClear`) and the new element `<olcad-measure-results>`; the test page and the vanilla example have a Measure toolbar and a Measure panel. Exported `MeasureTool`, `MEASURE_PROMPTS`, `MeasureStep`, `MeasurementsApi` and the measurement types.
- Parallel tool (`parallel`): select a line, polyline or polygon (read-only allowed), click a start point beside it (its distance and side fix the parallel; on the object it traces it), then follow the object with the crosshair: the dashed line runs parallel through every bend to the point nearest the crosshair (clamped at line ends, around rings past their first vertex); a click inserts it into the active or draft layer like a drawn line (or a typed plain number gives its length in metres). The reference stays for the next parallel; Escape and Backspace step back. Geometry in `src/core/geometry/parallel.ts` on top of a tolerant variant of the offset math (`offsetPath` in `src/core/geometry/offset.ts`: segments that collapse at the distance and crossed notch walls are skipped instead of refusing the whole parallel; refused only when nothing is left or a ring would turn inside out), plus a global cleanup that keeps the parallel at least its distance from every other part of the object (hairpins, pockets with a narrow mouth, self-crossing lines: it skips the vertices in between where its offsets cross, or ends) (`parallelPath` returning a `ParallelFailure` reason — `'unsupported'`, `'collapsed'`, `'too-close'` — when there is none, `subPath`, `stationOf`, `pathLength`). Toolbar button Draw parallel (icon `drawParallel`) in the Draw toolbar of the test page and the vanilla example; exported `ParallelTool`, `PARALLEL_PROMPTS`, `ParallelStep`.
- Moving drafts into a layer: `editor.layers.draftTargets(feature)` lists the layers a draft object can go to (insert allowed, geometry type fits; multi-part layers take single parts); `editor.layers.moveDrafts(features, layerId)` moves the selected drafts a layer takes as one command (deletes from the draft layer, inserts of copies with the layer's defaults under the objects' attributes; the copies are selected, `featureinsert` fires for each, one undo step), `moveDraft(feature, layerId)` for one; event `draftmove`. `<olcad-layer-list>` shows a Move selected draft button (`.olcad-layer-list__move-draft`, icon `moveToLayer`) on each layer row that takes the selected drafts; its new `reveal` attribute opens the Layers flyout when drafts are selected. `<olcad-attribute-form>` points a selected draft to the Layers panel and, with `reveal`, opens on the moved objects after `draftmove`; the popup asks for each copy.
- Ellipse tool (`ellipse`): one tool with three constructions (`ToolOptions.method`): `centre-axis` (centre, end of the first axis, other half-axis; the default), `axis` (both ends of the first axis, other half-axis) and `box` (two opposite corners of a box along the straightedge that the ellipse fills). The other half-axis is typed in metres (`Tool.handleValue`) or given by a point at that distance from the first axis. Linearized with `curves.tolerance` (circle segment count for the longer half-axis), inserted into the active or draft layer like a drawn polygon and selected. Flyout toolbar button Draw ellipse (icons `drawEllipse`, `drawEllipseAxis`, `drawEllipseBox`) in the Draw toolbar of the test page and the vanilla example; exported `EllipseTool`, `ELLIPSE_PROMPTS`, `ELLIPSE_METHODS`, `EllipseMethod`, `EllipseStep`, `ellipseMethod`, `DEFAULT_ELLIPSE_METHOD`, `ellipseFromCentre`, `ellipseFromAxis`, `ellipseFromCorners`, `ellipsePolygon`, `EllipseDefinition`.
- Scale tool (`scale`): select the objects (skipped when a selection exists), pick the base point, then type a factor (`2` doubles, `0.5` halves; `Tool.handleValue`) or pick a reference point and a target point (factor = distance base → target / base → reference; a plain length in the target step is metres from the base). Uniform, updatable objects only, one command, dashed preview; deselects afterwards; Escape and Backspace step back. Toolbar button Scale (icon `scale`) in the Modify toolbar of the test page and the vanilla example; exported `ScaleTool`, `SCALE_PROMPTS`, `ScaleStep`, `scaleGeometry`, `scaleFactor`.
- Mirror tool (`mirror`): select objects (skipped with a selection; read-only ones allowed), click or type the two points of the mirror line (dashed preview of the mirrored objects and the line), then `Create a copy? [y/N]` in the command line: Enter, `n` or a click mirrors the updatable objects in place (one command; read-only ones skipped with a notice), `y` / `j` inserts mirrored copies with the copied attributes into the source layer, else the active or draft layer (one composite), and the attribute popup opens for them. - `<olcad-attribute-form popup>` shows several inserts of one command one after another (progress `.olcad-attribute-form__progress`, "1 of 3"): Save and Later move on to the next, Escape closes for all; `closePopup()` now means "done with this one", new `closeAll()`. Before, only the last inserted feature was shown.

Removed: `__toggle`, `__badges`, `__badge*`, `__insert` and the "Insert into {title}" button that started the draw tool. Focus is kept on the pressed button across re-renders; hidden rows carry `__layer--hidden`.

- Test page and vanilla example: the buttons are grouped into three toolbars docked at the top: Main (edit mode, layer status, undo / redo, Select, Delete, zoom), Draw (point, line, polygon, rectangle, circle, regular polygon) and Modify (vertices, move, rotate).
- `InputResult` gained the variant `{ ok: true; text; value: number }` for plain numbers a tool takes as a value; hosts narrowing on `ok` must check `'coordinate' in result` before reading the coordinate. The `input-not-accepted` message now says "input" instead of "point" (en: "The active tool did not accept the input.", de: "Das aktive Werkzeug hat die Eingabe nicht übernommen.").
- **Breaking:** the `modify` tool no longer drags vertices with `ol/interaction/Modify` and no longer edits several selected objects at once; `canActivate('modify')` is `true` in edit mode regardless of the selection (the toolbar's Vertices button is always enabled in edit mode).

- **Breaking:** the move tool no longer drags the selection (`ol/interaction/Translate` is gone); it takes a base point and a second point. `canActivate('move')` is `true` in edit mode regardless of the selection. Backspace in the move tool steps back instead of deleting the selection.
